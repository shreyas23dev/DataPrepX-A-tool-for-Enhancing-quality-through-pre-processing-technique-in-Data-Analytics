================================================================================
  DataPrepX — Features & Capabilities Reference
  Smart Data Preprocessing Studio
================================================================================

DataPrepX is an interactive, terminal-based data preprocessing tool that
transforms raw datasets into clean, analysis-ready data. It provides a
guided, no-code workflow driven by questionary menus and rich terminal output,
and integrates a local Ollama LLM assistant that can inspect and directly edit
your data on request.

--------------------------------------------------------------------------------
1. FILE LOADING
--------------------------------------------------------------------------------

  • Accepts CSV (.csv) and Excel (.xlsx, .xls) files.
  • Files can be supplied at startup via the --file / -f command-line flag,
    or selected interactively through a file-path prompt with tab completion.
  • Graceful error messages are shown for missing or unsupported files.

  Usage:
      python cli.py                          # interactive file prompt
      python cli.py --file path/to/data.csv  # skip the prompt


--------------------------------------------------------------------------------
2. DATASET PREVIEW
--------------------------------------------------------------------------------

  Before any processing begins, DataPrepX can display a rich summary of the
  loaded dataset:

  • Total row and column counts.
  • Per-column table showing: column index, name, dtype, missing-value count,
    and a sample value.
  • The preview is optional — users can skip it to go straight to editing or
    configuration.


--------------------------------------------------------------------------------
3. MANUAL CELL EDITOR
--------------------------------------------------------------------------------

  An interactive cell-level editor lets users fix specific values in the
  dataset before the automated pipeline runs.

  Capabilities:
  • Column selection via autocomplete (supports partial name matching).
  • Row selection by zero-based integer index with range validation.
  • Context preview showing the 5 rows surrounding the chosen cell,
    with the target cell highlighted in yellow.
  • Three edit actions per cell:
      - Overwrite  : enter a new value (auto-cast to the column's dtype).
      - Set to NaN : mark the cell as missing.
      - Skip       : leave the current value unchanged.
  • Repeat editing as many cells as needed; choose "Done" to proceed.
  • A confirmation message with the new value is printed after each change.


--------------------------------------------------------------------------------
4. PREPROCESSING PIPELINE
--------------------------------------------------------------------------------

  The pipeline applies transformations in a fixed, reproducible order with a
  live progress bar. Each step is configurable.

  4a. TARGET COLUMN PROTECTION
  ─────────────────────────────
  • Select any column to protect as the target / label column.
  • The column is detached before all transformations and safely reattached
    afterward, ensuring it is never accidentally encoded, scaled, or dropped.

  4b. MISSING VALUE HANDLING
  ───────────────────────────
  Choose one of seven strategies:
      mean          — replace nulls with the column's arithmetic mean
      median        — replace nulls with the column's median
      most_frequent — replace nulls with the most common value (mode)
      constant      — replace nulls with a user-supplied fixed value
      ffill         — forward-fill (propagate the last valid observation)
      bfill         — backward-fill (propagate the next valid observation)
      drop          — remove all rows that contain at least one null

  4c. CATEGORICAL ENCODING
  ─────────────────────────
  Convert text / categorical columns to numbers for modelling:
      Label   — assign a unique integer to each category (sklearn LabelEncoder)
      One-Hot — create a binary indicator column per category (pd.get_dummies,
                boolean columns cast to int8 for memory efficiency)
      Ordinal — order-preserving integer encoding (sklearn OrdinalEncoder)
      None    — skip encoding entirely

  4d. OUTLIER HANDLING
  ─────────────────────
  Detect and remove outlier rows using:
      IQR               — remove rows where any numeric feature falls outside
                          1.5 × the interquartile range (classic Tukey fence)
      EllipticEnvelope  — multivariate robust covariance method that flags the
                          5 % most anomalous rows (sklearn EllipticEnvelope)
      None              — keep all rows

  4e. FEATURE SELECTION (VARIANCE THRESHOLD)
  ────────────────────────────────────────────
  Automatically drop near-zero-variance features that carry little predictive
  signal. Available thresholds: 0.00, 0.01, 0.05, 0.10, 0.20.
  (sklearn VarianceThreshold; non-numeric columns are preserved unchanged.)

  4f. FEATURE SCALING
  ─────────────────────
  Normalise numeric columns so their ranges are comparable:
      Standard — zero mean, unit variance (z-score normalisation)
      MinMax   — rescale to [0, 1]
      Robust   — median-based scaling, less sensitive to outliers
      None     — skip scaling


--------------------------------------------------------------------------------
5. OUTPUT FORMATS
--------------------------------------------------------------------------------

  After the pipeline completes, the processed dataset can be saved in up to
  three formats simultaneously (selected via checkbox prompt):

  • CSV  — processed_<original_filename>.csv
  • JSON — processed_<original_filename>.json  (records orientation, indented)
  • XLSX — processed_<original_filename>.xlsx  (via openpyxl)

  The output directory can be set to any path; it defaults to the same
  directory as the input file.

  A job_config.json file is always written alongside the outputs containing
  every configuration choice made during the session — source file, all
  preprocessing parameters, and output paths — for full reproducibility.


--------------------------------------------------------------------------------
6. OLLAMA LLM ASSISTANT
--------------------------------------------------------------------------------

  DataPrepX integrates a local LLM (served via Ollama) as an interactive data
  assistant. The assistant is available at TWO stages of the workflow:

      Stage 1 — Raw Data    : after loading, before preprocessing
      Stage 2 — Processed   : after the pipeline finishes

  6a. MODEL SELECTION
  ────────────────────
  • Automatically queries the local Ollama server (http://localhost:11434) for
    all available models.
  • Presents a menu of installed models; defaults to llama3.2 if present.
  • Falls back gracefully with a clear error if Ollama is not running.

  6b. DATASET CONTEXT
  ─────────────────────
  • A compact snapshot of the DataFrame (shape, column names, dtypes, null
    counts, sample values, and the first 3 rows) is injected into the LLM's
    system prompt so it can answer questions without needing external data.

  6c. TOOL: query_data
  ─────────────────────
  • The LLM can run arbitrary pandas expressions against the live DataFrame
    to answer statistical or exploratory questions.
  • Examples of what users can ask:
      "What is the average Age?"
      "Show me the value counts for the Status column."
      "Which row has the highest Salary?"
  • Expressions are sandboxed — a blocklist prevents access to os, sys,
    subprocess, open, eval, and other dangerous identifiers.
  • Tool calls are detected from the model's JSON code-block output and
    executed automatically; results are fed back to the model so it can
    respond in natural language.

  6d. TOOL: edit_cell  ← NEW
  ───────────────────────────
  • The LLM can now write values back into specific DataFrame cells based on
    the user's plain-English instructions.
  • Parameters:
      column    — the exact column name to target
      row_index — the zero-based integer row index
      new_value — the value to write (automatically cast to the column dtype)
  • Dtype-aware casting:
      integer columns  → int   (handles "3.0" → 3)
      float columns    → float
      boolean columns  → bool  ("true"/"yes"/"1" → True, otherwise False)
      string/object    → kept as string
      "nan"/"null"/"none"/"" → np.nan (marks as missing)
  • Validation errors (unknown column, out-of-range row, bad cast) are
    returned as descriptive error strings — the DataFrame is never corrupted.
  • Column-name suggestions are provided when a near-match is found.
  • Examples of what users can ask:
      "Set row 5, column ProductName to 'Unknown'."
      "Fix the Age in row 12 — it should be 34."
      "Mark the Score in row 0 as missing."

  6e. EDIT AUDIT LOG
  ───────────────────
  • Every successful LLM-driven cell edit is recorded in an in-memory audit
    log during the chat session.
  • When the user types "exit" or "quit", a formatted table is printed showing:
      Column | Row | Old Value | New Value
  • This gives full transparency over every change the LLM made before the
    data flows into the preprocessing pipeline or is saved to disk.

  6f. STREAMING RESPONSES
  ────────────────────────
  • All LLM replies are streamed token-by-token directly to the terminal for
    a responsive, real-time feel.
  • The first call is made silently (for tool-call detection); if no tool is
    invoked, a second streaming call is made and printed live.


--------------------------------------------------------------------------------
7. PIPELINE REPRODUCIBILITY
--------------------------------------------------------------------------------

  Every run produces a job_config.json file capturing:
      source_file, target_column, missing_method, fill_value,
      encoding, scaler, outlier_method, variance_threshold,
      output_formats, output_directory

  Re-running cli.py with the same dataset and these settings will produce an
  identical output, making experiments fully auditable and shareable.


--------------------------------------------------------------------------------
8. TERMINAL UX & DESIGN
--------------------------------------------------------------------------------

  • Rich library: coloured panels, rule separators, progress bars with spinner
    and elapsed-time column, bordered tables, and styled text throughout.
  • questionary library: arrow-key selection menus, checkboxes, autocomplete
    inputs, text prompts with inline validation, and confirm dialogs.
  • Ctrl-C / EOF are handled gracefully at every interactive prompt.
  • All prompts use a consistent teal/cyan colour scheme (Q_STYLE).


--------------------------------------------------------------------------------
9. DEPENDENCIES
--------------------------------------------------------------------------------

  Core:
      pandas        — DataFrame I/O and all data manipulation
      numpy         — numeric types and NaN handling
      scikit-learn  — encoders, scalers, outlier detectors, feature selector

  Terminal UI:
      rich          — styled terminal output, tables, progress bars
      questionary   — interactive prompts and menus

  Output:
      openpyxl      — Excel (.xlsx) read/write support

  LLM Integration:
      requests      — HTTP calls to the local Ollama API
      ollama        — local LLM server (external, must be running separately)

  Optional / legacy:
      gradio        — original Gradio UI (earlier version of the project)
      ydata-profiling — HTML profiling reports
      ipython       — notebook compatibility


--------------------------------------------------------------------------------
10. QUICK-START
--------------------------------------------------------------------------------

  1. Install dependencies:
         pip install -r requirements.txt

  2. (For LLM features) Start Ollama and pull a model:
         ollama serve
         ollama pull llama3.2

  3. Run DataPrepX:
         python cli.py
         python cli.py --file my_dataset.csv

  4. Follow the on-screen prompts to:
         a. Preview your dataset
         b. Edit individual cells manually or via the LLM
         c. Chat with the LLM about your raw data
         d. Configure the preprocessing pipeline
         e. Confirm and run
         f. Chat with the LLM about the processed results
